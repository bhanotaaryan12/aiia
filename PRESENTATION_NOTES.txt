1. EXECUTIVE SUMMARY & CORE MISSION
================================================================================
The AIIA CTMS is a cloud-ready, real-time Clinical Trial Management System 
specifically tailored for Ayurveda clinical research (Rasayana, Panchakarma, 
herbal formulations). 

Key Differentiators:
* Rigorous Compliance: Built around CDSCO Good Clinical Practice (GCP) and New 
  Drugs and Clinical Trials (NDCT) Rules 2019.
* Global Standards: Native CDISC (CDASH collection, SDTM export) and HL7 FHIR R4 
  interoperability.
* AI-Powered Context Memory: Integrates a deterministic and semantic knowledge 
  graph engine (powered by Graphify) allowing multi-tenant, privacy-isolated 
  conversational memory for investigators and study teams.
* Presentation Safety: Features dedicated, strictly isolated presentation safeguards 
  and mock walkthrough records that guarantee zero exposure of live patient or trial data.

4. CONTEXT MEMORY ENGINE (GRAPHIFY-POWERED KNOWLEDGE GRAPH)
================================================================================
The CTMS features an advanced Context Memory Engine that maps interactions,
preferences, and clinical facts into an evolving knowledge graph.

Key Architecture Components:
* TenantGraphStorage:
  Guarantees 100% tenant and investigator data isolation. Each user's memory graph 
  is persisted in a secure, hashed namespace (`user_<sha256>.json`).
* MemoryExtractionPipeline:
  Extracts entities (Users, Trials, Ethics Committees, Formulations, Preferences) 
  and edges (INVESTIGATES, APPLIES, COMPLIES_WITH, PREFERS). 
  Applies honest confidence tagging: EXTRACTED vs INFERRED.
* MultiFactorRanker:
  Calculates dynamic contextual relevance using:
    Score = (w_rel * relevance) + (w_prox * proximity) + (w_conf * confidence) + (w_rec * recency)
  Applies exponential recency decay to prevent stale memories from polluting context.
* AgentMemoryLifecycle:
  Acts as middleware for assistant turns:
    - before_agent_turn: Retrieves subgraphs, ranks relevant nodes, builds ContextPackage.
    - after_agent_turn: Ingests turns, deduplicates entities, updates graph store.
* Codebase Knowledge Graph (Graphify Artifacts):
  The repository itself is indexed in `graphify-out/`:
    - 732 nodes, 1,874 edges across 56 semantic communities.
    - Interactive visualizer in `graphify-out/graph.html`.
    - Markdown topology report in `graphify-out/GRAPH_REPORT.md`.

8. ANTICIPATED AUDIENCE Q&A / TALKING POINTS
================================================================================

Q1: "How does the system ensure patient privacy during trials and demonstrations?"
A1: Three complementary safeguards:
    1. Architectural: Participant records use pseudonymous identifiers (e.g. AIIA-1-0001) 
       with zero storage of direct government IDs in primary operational tables.
    2. Demonstration Isolation: Presentation records are mock walkthrough records 
       stored in a protected API namespace that rejects all non-demo credentials.
    3. Multi-Tenant Memory: Memory graphs are SHA-256 hashed and isolated per tenant.

Q2: "What is the difference between CDASH and SDTM in your CDISC implementation?"
A2: CDASH governs how data is captured in forms at the clinical site (our eCRFs).
    SDTM governs how the data is standardized and structured for submission to regulatory
    authorities. Our system automatically transforms CDASH form submissions into
    compliant SDTM domains (DM, SV, AE) with instant CSV/JSON exports.

Q3: "Why use a graph for memory instead of simple vector search (RAG)?"
A3: Vector search struggles with multi-hop reasoning (e.g., "Which ethics committee
    approved the protocol amendment for the site with the highest SAE count?").
    Graphify turns entities and relationships into a typed network, enabling exact
    relational queries, community discovery, and honest confidence scoring without hallucination.

Q4: "Can this system be deployed on institutional government servers?"
A4: Yes. The system is containerized with Docker, supports both cloud environments (GCP Cloud Run) 
    and completely air-gapped on-premises deployments with local PostgreSQL and local file storage.
